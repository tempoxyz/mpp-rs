mpp: minor

Refused Tempo session challenges whose realm is not the request's hostname unless `with_trusted_tempo_proof_realm` pins it for that origin, as zero-amount proofs already were; a WebSocket URL is checked against its host, and any other URL, such as an MCP resource, trusts only a realm pinned for its scheme, host and port, as mppx does. Session providers now only reuse, overwrite or delete stored channels they own: a provider bound to an HTTP origin owns channels bound to that origin, and an unbound one owns channels stored without an origin. A bound provider leaves a channel stored without an origin (a legacy entry, or one an unbound provider paying the same payee keeps) in place and keeps the channel it opens under `store::origin_channel_key` (`<scope key>@<origin>`), and an unbound provider treats a channel bound to an origin as absent, so it never signs a close, voucher or top-up for another origin's channel or names it to another origin. Writing a legacy entry's own channel, such as one recovered from a server snapshot, updates that entry in place. A channel stays under the key it was read from or written to while the provider holds it, even after the provider is bound, and is only deleted there once confirmed unfunded. Closing a channel now checks it against the store before signing, as top-ups and vouchers do. Reading a stored channel never binds a provider; a store namespaced by one HTTP origin, such as a `SqliteChannelStore` for an `https://` namespace, binds its providers to that origin through the new `ChannelStore::origin`. Recovering a channel the store does not hold from a server snapshot now requires `TempoSessionProvider::with_origin` or `TempoAccountsProvider::with_session_origin`, as mppx does.

Breaking: `ChannelStore` has a new required method, `set_at`, which stores an entry under a key other than its payment-scope key; custom stores must implement it (and `get` and `delete` must then find and remove that key) to compile.

Migration: servers left on the default `"MPP Payment"` realm or a platform app-name realm must set `.realm(<host>)` or trusted request hosts so clients accept their session challenges, or clients must pin the realm with `with_trusted_tempo_proof_realm`. Custom `ChannelStore`s implement `set_at`, for example by keeping entries in a map keyed by `key` as `MemoryChannelStore` does. Stored channels written without an origin are no longer reused once a provider is bound, but stay under their payment-scope key; close them with a provider that has no HTTP origin, for example through `close_with`, to reclaim their deposits, or pin the provider with `with_origin` before its first payment so the channels it writes carry an origin.
