Refused Tempo session challenges whose realm is not the request's hostname unless `with_trusted_tempo_proof_realm` pins it for that origin, as zero-amount proofs already were, including a cached Challenge a prepaid voucher would be signed for, which is checked against the current request and caller's pins before signing; a WebSocket URL is checked against its host, and any other URL, such as an MCP resource, trusts only a realm pinned for its scheme, host and port, as mppx does. Stored session channels are now kept separately per HTTP origin: a session provider bound to an origin reads and writes channels only in that origin's namespace, under `store::origin_channel_key` (`<scope key>@<origin>`), and a provider without an origin only under the payment-scope key, where legacy entries written before origins existed also stay. Providers sharing a store never reuse, recover, overwrite, rebind or delete each other's channels, and a server snapshot naming a channel another namespace keeps is skipped, so the provider opens its own channel instead of failing or copying it. A channel a provider used before it was bound stays in the namespace without an origin, and once bound the provider no longer signs vouchers, top-ups or closes for it. Closing a channel now checks it against the store before signing, as top-ups and vouchers do. Reading a stored channel never binds a provider; a store namespaced by one HTTP origin, such as a `SqliteChannelStore` for an `https://` namespace, binds its providers to that origin through the new `ChannelStore::origin` and keeps that origin's channels under their payment-scope key, as mppx does. Recovering a channel the store does not hold from a server snapshot now requires `TempoSessionProvider::with_origin` or `TempoAccountsProvider::with_session_origin`, as mppx does.

Breaking: `ChannelStore` has a new required method, `set_at`, which stores an entry under a key other than its payment-scope key, and `find_channel`, which returns the key a channel is stored under; custom stores must implement both (and `get` and `delete` must then find and remove the key `set_at` used) to compile.

Migration: servers left on the default `"MPP Payment"` realm or a platform app-name realm must set `.realm(<host>)` or trusted request hosts so clients accept their session challenges, or clients must pin the realm with `with_trusted_tempo_proof_realm`. Custom `ChannelStore`s implement `set_at`, for example by keeping entries in a map keyed by `key` as `MemoryChannelStore` does, and `find_channel`, by searching every key for the channel ID, so a provider never recovers a channel another origin's namespace keeps. Stored channels written without an origin stay under their payment-scope key and are no longer used by providers bound to an origin; close them with a provider that has no HTTP origin, for example through `close_with`, to reclaim their deposits. Opening a `SqliteChannelStore` moves each channel an earlier release bound to an origin under its payment-scope key, in a namespace that keeps several origins' channels (such as `wallet`), into that origin's namespace; other rows stay where they are. In a custom store, such a channel is refused by providers without an origin until it is moved to `origin_channel_key(key, origin)`.
