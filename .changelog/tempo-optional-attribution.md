Changed Tempo charge verification of transaction credentials to accept a transfer without an attribution memo or with a non-attribution memo where the server configured none, since the server broadcasts the client's own transaction, and to reject any attribution memo there that is not bound to this challenge and realm, including another realm's, so a transfer settled here cannot later be claimed at that realm as a hash credential; memos the server configures are still matched exactly. Hash credentials still require attribution bound to the challenge and realm, so a transfer someone else made cannot be claimed. Unbound attribution, or a hash credential without bound attribution, now fails as a verification failure (402) instead of a replayed credential. A settled transaction's hash is recorded in the same replay record hash credentials are checked against. Tempo charge challenges now emit amounts without leading zeros, proof credentials signed by an access key now require AccountKeychain to name that key, and amounts with leading zeros are accepted and compared numerically.
